## 3. Key architectural facts worth remembering

- **Two parallel embedding/vector stacks.** Ingestion **and query** (since the I-02 fix) use legacy `services/embeddings.py`
  (fastembed MiniLM-384) plus `services/pinecone_service.py`. The provider-registry embedder is not used for retrieval. The registry `VectorStore` is only used by the startup
  guard and `reembed.py`. Unifying these is the biggest structural debt.
- `app/db/sqlite.py` is a shim over repositories (SQLite or SQLAlchemy). Add DB functions in 4 places
  (ABC, sqlite_repo, sqlalchemy_repo, shim).
- Pinecone holds chunk vectors (default namespace) with full text in metadata, plus a `documents_registry` namespace
  (one unit-vector record per doc). Many document endpoints read **only** from that registry.
- Lexical BM25 is per-tenant, in memory, cached to `data/lexical/lexical_{family}.json`, and rebuilt at startup.
- SSE pipeline: `stream_rag_events` is the single source; `execute_rag_query` drains it.
- Postgres RLS exists only via alembic migrations. `init_db()` on Postgres uses `create_all` (no RLS).
